INFINITY STOCK V11.16 - USUÁRIOS, PERMISSÕES E SESSÃO OFFLINE

Base:
- ZIP enviado pelo usuário: consulta-sementes-main (3).zip

CORREÇÕES PRINCIPAIS

1) NOVO USUÁRIO SEM DIGITAR SENHA
- O cadastro de usuário não solicita senha inicial.
- A senha padrão é: conceito123
- O backend ignora qualquer senha enviada na criação e usa a senha padrão.
- O perfil é marcado como primeiro acesso.

2) TROCA OBRIGATÓRIA NO PRIMEIRO LOGIN
- O middleware agora usa PerfilUsuario.primeiro_acesso como fonte de verdade.
- Enquanto primeiro_acesso=True, nenhuma página do sistema é liberada antes da troca.
- A senha atual é realmente validada na tela de troca.
- A nova senha não pode ser a senha padrão nem igual à senha atual.
- Reset de senha volta a marcar primeiro_acesso=True.
- JWT offline antigo é recusado enquanto a troca obrigatória estiver pendente.

3) REDIRECIONAMENTO CONFORME PERMISSÃO
- Depois do login/troca de senha, o usuário vai para a primeira tela explicitamente permitida.
- Exemplo: usuário apenas com Almoxarifado abre direto no Almoxarifado.
- Dashboard não é mais liberado apenas por ter Estoque.
- URL sem permissão redireciona para uma tela permitida, não para Dashboard à força.

4) PERMISSÕES INDIVIDUAIS COMO FONTE DE VERDADE
- Grupos antigos deixam de conceder permissões ocultas.
- A migração 0045 normaliza contas existentes:
  * se a conta já tem permissões individuais, elas prevalecem e grupos são removidos;
  * se a conta legada só dependia de grupo, as permissões do grupo são copiadas para individuais antes da remoção;
  * permissões antigas de Almoxarifado gravadas no app sapp são migradas para o app almoxarifado correto.
- Novos usuários nunca recebem grupos.
- Ao salvar permissões, os grupos são limpos e apenas os checkboxes selecionados permanecem.

5) TELA DE PERMISSÕES CORRIGIDA
- Removido seletor de Grupo de Acesso.
- Adicionada permissão de Dashboard.
- Almoxarifado aparece também no modal de edição de permissões.
- Removida permissão Configurações duplicada.
- O formulário informa claramente que somente as opções marcadas serão liberadas.

6) SESSÃO OFFLINE EXPIRADA
- A tela de troca obrigatória de senha não inicializa o bloqueio offline.
- Quando o navegador está online, um token offline local expirado é renovado antes de exibir status de sessão.
- O modal de bloqueio por sessão expirada só cobre a tela quando o dispositivo está realmente offline.
- Cache offline atualizado para a nova versão.

DEPLOY
1. Subir a versão.
2. Executar: python manage.py migrate
3. Executar: python manage.py collectstatic --noinput
4. Reiniciar/rebuild do serviço.
5. No navegador, fazer Ctrl+F5 uma vez.

IMPORTANTE
- Esta versão TEM migração nova (0045).
- Não altera estoque, empenho, quantidade, movimentação ou cargas.

AJUSTE ADICIONAL DE GRUPOS LEGADOS
- sapp/management/commands/create_groups.py não adiciona mais permissões a grupos.
- almoxarifado/signals.py não injeta mais permissões automáticas em grupos.
